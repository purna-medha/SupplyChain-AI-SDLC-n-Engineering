# B1–B3 container help desk labs

## Intent and design

Build two versions of the same three-module lab: a standalone container help
desk and a PortOps extension. Learners implement small TODO functions; supplied
data, CLI commands, model setup and persistence let them run one checkpoint at
a time. No completed learner solution is shipped.

The progression follows the current `slides-md` and numbered snippets:

1. B1: general terminology, instructions, real conversation history and actual
   usage/latency measurements. Hosted/local comparison is optional.
2. B2: direct reads, an SDK tool agent, then the same capabilities through MCP.
   The LlamaIndex comparison remains an optional transfer from the snippets.
3. B3: prescribed routing, an agent investigation, saved draft/conversation,
   then an actual SDK approval interruption and local review outbox.
   Coordinator and handoff arrangements are optional extensions.

Implementation choices: Python 3.11+, LiteLLM for B1, OpenAI Agents SDK 0.20.0
and MCP 2.3.0 for B2/B3, matching the taught examples. Each module is runnable
independently; B3 supplies its own completed read adapters. An unfinished TODO
prints its checkpoint and exits nonzero, never pretending a model succeeded.

Standalone records are fixed synthetic fixtures. The PortOps adapter uses only
existing HTTP GET endpoints, scopes the overview to a configured importer and
checks membership before requesting a fee. It reuses the API's calculation;
learners do not recreate tariffs or infer tracking events the API cannot expose.
The importer setting is a classroom scope, not authentication. B1 connects no
records. Review queues only a local draft; no email, claim or gate-out operation.

## Review focus

- Unknown IDs and another importer's IDs must not become a known status or fee.
- A blocked TODO and an exhausted run must not be printed as completion.
- Review must show exact pending arguments; reject/invalid input executes no action.
- State/history files belong to this lab and cannot silently resume another case.
- Both lab copies must run from the documented working directory, including
  subprocess MCP startup, without relying on a sibling project import.

Work is additive in the existing checkout to preserve substantial staged and
unstaged workshop authoring. No automatic commits or worktree switch.
