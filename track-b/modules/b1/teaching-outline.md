# B1 teaching intentions

Module question: How does a generated answer become usable application data?

## 1. Understand the generation boundary
- Distinguish generating language from retrieving a stored operational record.
- Inspect one real message request and actual answer.
- Predict which properties change with a style instruction.
- Reveal instruction influence and the absence of an executable guarantee.
- Separate instruction, task and supplied evidence.

## 2. Supply evidence and conversational continuity
- Predict what an identifier alone establishes about its fee.
- Compare the same question with missing and supplied facts.
- Explain context as request data rather than training.
- Introduce tokens and the finite request budget without fixed token claims.
- Predict the ambiguity of a follow-up without earlier messages.
- Inspect explicit history and explain the cost of retaining it.

## 3. Establish usable structure and permission
- Motivate named fields through a concrete downstream decision.
- Parse the actual model reply and preserve failures.
- Predict syntax acceptance separately from useful shape.
- Define a schema and predict valid, unsupported and extra-field outcomes.
- Reveal validation reasons; distinguish permission from shape.
- Diagnose a rejected status and repair the responsible boundary.

## 4. Compare and transfer
- Compare quality before latency and usage on the same task.
- Interpret a prepared faster-but-wrong example without presenting a benchmark.
- Trace a worked schema example; complete the guided permission check.
- Add an unsupplied policy for missing container evidence.
- Explain which facts and checks would later connect to PortOps.

## Five execution checkpoints

01 request inputs (call + controlled evidence/style comparison); 02 history; 03 generated text/JSON/schema; 04 deterministic validation/scope; 05 model comparison. The conceptual slides unfold these five exercises rather than introduce additional required scripts.

## Teaching snippets and activities

Teach s01 model call, s02 instruction, s03 context, s04 history, s05 JSON, s06 schema, s07 permission and s08 comparison as separate mechanisms.
