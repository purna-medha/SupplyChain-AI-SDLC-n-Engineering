# B5 lab · Diagnose and verify one repair

**Start:** open [b5.py](b5.py) and implement `make_cases` and `grade_observation`. Run `python b5.py probe` before trusting a score.

A fee assistant reports that C2 is clear even though the classroom policy requires review at **USD 200 or more**. Establish the expectation, locate the first wrong observation, repair that rule and compare the same tasks from fresh state.

Use the [B5 slides](../../slides-md/b5-safety-observability-evaluation.md) and [complete examples](../../snippets/b5/README.md). Complete [lab setup](README.md#prepare-once). Commands run **from this lab folder with its environment active**. B4 and earlier TODOs are not imported.

**Plan 60 minutes:** about 45 for five checkpoints, 10 for two experiments and 5 to explain the evidence. This estimate still needs an instructor timing run. Model latency varies.

## The independent B5 fixture

Caller A owns C1 with recorded fee 100 USD and C2 with 200 USD. C9 is absent. Caller B cannot obtain either known fee. A simulated unavailable source supplies no fee. This is a separate fixture from B4 and the B1–B3 help desk records.

The supplied baseline uses `fee > 200`. Leave it unchanged. Your candidate function will implement the repair. The model is instructed to report the tool's decision unchanged, so the trace can expose where the error originated.

## 1 · Define cases and verify the checker · 12 minutes

Implement **B5.1 `make_cases()`**. Each dictionary must contain `name`, `caller`, `container_id`, `unavailable`, `expected_fee` and `expected_decision`.

| Name | Caller | ID | Unavailable? | Expected fee | Expected decision |
| --- | --- | --- | --- | --- | --- |
| below | A | C1 | False | 100 | clear |
| boundary | A | C2 | False | 200 | review |
| missing | A | C9 | False | None | unknown |
| denied | B | C2 | False | None | denied |
| dependency | A | C2 | True | None | unavailable |

These references come from the policy, independently of `observe_fee`.

Implement **B5.2 `grade_observation(expected, actual)`**. `expected` contains `container_id`, `fee` and `decision`. Return a real boolean requiring those fields, matching ID/decision, matching fee and its exact type. A text/bool amount must not pass an integer requirement. Missing fields must fail; a legitimate absent fee is `None`. Ignore additional source metadata.

**Predict:** would an always-true checker distinguish 200 from 999?

```bash
python b5.py probe
```

**Inspect:** the correct observation is accepted; wrong amount/ID/decision/type and missing fee are rejected. A disagreement stops with `Grader defect`. This command is offline. Fix the checker before continuing.

## 5 · Compare repeated real agent attempts · 12 minutes

**Predict:** should C1 and C9 change when only the boundary rule changes?

```bash

```

The runner selects the three caller-A available/missing cases, makes two attempts per case/version and starts each attempt with a new agent conversation and empty tool-call list. This is **12 real agent trials**; each can involve multiple model calls.

**Inspect:** each actual label, observation, requested ID, error and pass/fail outcome. A trial passes only when it has a successful observation, the expected final label, the correct requested ID(s) and a passing field check. Errors and incomplete attempts remain in the fixed denominator.

## Explore the same lab · choose two

1. **Can the checker hide the failure?** Temporarily replace `grade_observation`'s body with `return True`, then run `python b5.py probe`. Identify the rejecting probe and restore the checker before continuing.
2. **Does the repair preserve neighboring behavior?** Run `python b5.py trace --container C1 --repaired`, then C9. Compare actual observations with clear/unknown expectations; an absent fee must remain absent.
3. **Does an incomplete attempt disappear?** Run `python b5.py trials --max-turns 1 --repeats 1`. Inspect all three attempts in each version and their denominators. A query/tool operation may execute before the agent stops. This command replaces the previous `b5-trials.json`; retain a copy first if comparing reports.
4. **Does one repair fix a different layer?** Run `python b5.py trace --repaired`. If an answer exceeds a correct tool observation, locate that separate mismatch instead of changing the fee rule again.
5. **Can two successes establish reliability?** Change `--repeats` for the same cases. Report the actual counts, configuration and task scope. Include errors/stops and account for the additional calls; do not show only the best attempt.

Use the [same-lab exploration method](../EXPLORATION.md). Each command overwrites only its own named B5 report in `work/`; reports from different checkpoints are separate. No external messages are sent.
