# B2 · Answer a recorded container enquiry

**Use case:** a customer asks for a container's status and net demurrage.
General model knowledge cannot establish either fact. Build two small read
capabilities, let an agent use them, then share them through MCP.

Review the [B2 slides](../../slides-md/b2-tools-and-mcp.md) and
[numbered B2 snippets](../../snippets/b2/README.md). Complete the
[lab setup](README.md). This module does not depend on your B1 code.

## 1. Make the application reads useful · about 15 minutes

Edit **B2.1 `read_status(container_id)`** and **B2.2 `read_fee(container_id)`**
in `b2.py`. Use the supplied `get_container` and `get_demurrage` adapters;
they return a dictionary or `None`. Inspect `records.py` to find the field
names. The TODO comments specify each returned dictionary.

- Status: return the requested ID, observed status and `SOURCE`. If absent,
  use the label `unknown`.
- Fee: return the requested ID, observed **net payable** USD amount and
  `SOURCE`. If absent, use `None`, not a zero fee.

```bash
python b2.py direct
python b2.py direct --container C2
python b2.py direct --container C9
```

**Observe:** both direct results have the requested ID and source. C2's known
zero fee differs from C9's missing fee. These are ordinary Python reads; no
model has run. Do not calculate another fee in the prompt or read function.

## 2. Let the agent request the facts · about 20 minutes

Implement **B2.3 `make_agent()`**. Construct an `Agent` using the provided
instruction and the taught model. Register your two functions with
`function_tool`. Use `failure_error_function=None` so an unfinished TODO or
failed read propagates visibly during this learning exercise.

```bash
python b2.py agent
python b2.py agent --container C9
python b2.py agent --question "What is demurrage in shipping?"
```

**Observe:** for the default enquiry, locate actual READ output before
accepting the answer. Check ID, status, net amount and USD against the source.
For C9, check that no status/fee is invented. For the definition, inspect
whether any operational read was necessary. Tool selection is model behavior
to inspect, not a guaranteed trace.

## 3. Share the same reads through MCP · about 20 minutes

The supplied `mcp_server.py` imports and publishes your two read functions. It
contains no duplicate records or different implementation. Implement **B2.4
`make_mcp_agent(server)`** using `mcp_servers=[server]`. Keep the instruction
and model; use no in-process read tools on this agent.

In terminal A, from this lab folder with its environment active:

```bash
python mcp_server.py
```

In terminal B, from the same folder with the same environment active:

```bash
python b2.py mcp
python b2.py mcp --container C9
```

**Observe:** terminal B lists the discovered tools; terminal A prints actual
reads. Compare the final answer with the direct read. Explain which process
owns the function, which process owns the model interaction, and how the
observation returns. Stop terminal A with Ctrl+C after the exercise. Restart
it after changing a function or its records.

If startup reports that the port is occupied, use `python mcp_server.py --port
8891` and pass `--mcp-url http://127.0.0.1:8891/mcp` to the client. The default
port is listed in the lab README. An unavailable server is a connection
failure, not an unknown-container result.

## 4. Explain the working boundary · about 5 minutes

Completion evidence: direct status/fee output, actual agent-requested reads,
MCP discovery and server-side execution, plus an unknown-ID result.

Explain why a function schema does not itself contain a record, why a tool
result is needed before answering, and why a valid string ID may still be
absent. Keep production authorization separate from this classroom lookup.

**Optional transfer:** adapt the supplied LlamaIndex direct-tool or MCP
client snippet to reuse these same two capabilities. Compare observations,
not just framework class names. A second framework is not needed to finish
the core lab.
